Six patterns, from fixed to free

Each row is a wiring diagram in the same notation: red capsules are LLM calls, squares are your code or tools, diamonds are gates, dashed wires are decided at run time.

  1. 1Prompt ChainingDecompose a task into a fixed sequence of steps; each LLM call processes the previous output, with optional checks between.WorkflowCost / latencyLow–mediumBest forCleanly decomposable fixed subtasks
  2. 2RoutingClassify the input first, then send it to a specialized follow-up — a different prompt, tool chain, or model.WorkflowCost / latencyLow (+1 classify)Best forDistinct categories handled separately
  3. 3ParallelizationRun multiple LLM calls at once and aggregate the results. Two variants: sectioning and voting.WorkflowCost / latencyHigher (×N calls)Best forIndependent subtasks; multiple attempts
  4. 4Orchestrator–WorkersA central LLM dynamically breaks down the task, delegates to worker LLMs, and synthesizes their results.WorkflowCost / latencyHighBest forSubtasks can't be predicted up front
  5. 5Evaluator–OptimizerOne LLM generates a response while another evaluates and gives feedback, in a loop — iterative refinement.WorkflowCost / latencyMedium–high (loop)Best forClear criteria; refinement adds value
  6. 6Autonomous AgentsNo fixed path. The LLM plans and acts in a loop, using tools and environmental feedback to direct itself toward a goal.AgentCost / latencyHighest, variableBest forOpen-ended; steps can't be hardcoded

The real dividing line: who controls the flow

The dividing line is who controls the flow. In a workflow, the control flow is fixed in code you wrote; the LLM fills in the steps. In an agent, the LLM itself decides what to do next and keeps control over how the task gets done.

Workflows are systems where LLMs and tools are orchestrated through predefined code paths. Agents are systems where LLMs dynamically direct their own processes and tool usage. — Anthropic
