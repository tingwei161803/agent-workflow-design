六種模式，由固定到自主

每一列都是同一套記號畫的接線圖：紅色膠囊是 LLM 呼叫，方塊是你的程式或工具，菱形是關卡，虛線代表執行時才決定的路徑。

  1. 1提示鏈 Prompt Chaining把任務拆成固定的循序步驟，每步 LLM 呼叫處理上一步的輸出，中間可加檢查。工作流成本／延遲低～中最適合能乾淨拆成固定子任務
  2. 2路由 Routing先把輸入分類，再分派給專門的後續處理 —— 不同的提示、工具鏈或模型。工作流成本／延遲低（多一次分類）最適合明確類別、分開處理更好
  3. 3平行化 Parallelization同時跑多個 LLM 呼叫再彙整結果。兩種變體：分節（sectioning）與投票（voting）。工作流成本／延遲較高（×N 次呼叫）最適合獨立子任務；多次嘗試
  4. 4協調者—工作者 Orchestrator–Workers由中央 LLM 動態拆解任務、分派給工作者 LLM，再彙整它們的結果。工作流成本／延遲高最適合子任務無法事先預測
  5. 5評估者—優化者 Evaluator–Optimizer一個 LLM 產生回應，另一個評估並回饋，形成迴圈 —— 反覆迭代精修。工作流成本／延遲中～高（迴圈）最適合標準明確；精修有價值
  6. 6自主代理 Autonomous Agents沒有固定路徑。LLM 在迴圈中規劃並行動，靠工具與環境回饋自我導向達成目標。代理成本／延遲最高、浮動最適合開放性；步驟無法寫死

真正的分界：誰掌控流程

分界在於「誰掌控流程」。工作流裡，控制流程是你寫死在程式中的，LLM 只負責填內容；代理裡，是 LLM 自己決定下一步要做什麼，並持續掌控任務如何完成。

工作流是『LLM 與工具透過預先定義的程式路徑被編排』的系統；代理則是『LLM 動態主導自己的流程與工具使用』的系統。— Anthropic
